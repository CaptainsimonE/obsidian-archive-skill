# 归档模板集（templates）

归档时的唯一格式依据，四种类型对应不同落点。字段与结构均从用户库内既有笔记归纳，不要随意改动。

## 一、知识笔记（30-Resources 主题文件夹）

**文件名**：`<主题短语>.md`（例：`Git.md`、`先记录后整理，降低认知负担.md`）

```yaml
---
title: <一句话主题>
created: YYYY-MM-DD
tags:
  - <主题标签>
  - <关键词1>
  - <关键词2>
source: "WorkBuddy 问答归档"
up: "[[-00-主题MOC]]"   # 仅当目标文件夹已有 MOC 时添加，否则整行删除
---
```

正文**不写 H1**：

```markdown
## 核心结论

> 一到两句话直接回答（引用块）

## 要点

- 要点 1：……
- 要点 2：……

## 详细说明

按需分 `### 小节`，保留原理/步骤/代码/对比表。

## 相关笔记

- [[已有笔记名]]
```

## 二、对话总结（30-Resources 主主题文件夹 / 00-Inbox）

**文件名**：`<主题>-对话总结.md`（例：`知识管理-对话总结.md`；主题分散落 Inbox 时用 `<日期>-对话总结.md`）

```yaml
---
title: <对话主题>（对话总结）
created: YYYY-MM-DD
tags:
  - <主题标签>
  - 对话总结
source: "WorkBuddy 问答归档"
up: "[[-00-主题MOC]]"   # 仅当主题文件夹已有 MOC 时添加
---
```

```markdown
## 背景

- 这次对话围绕什么问题展开（1-2 行）

## 核心结论

- 结论 1：……
- 结论 2：……

## 要点

分条归纳问答中的关键信息，保留数字、命令、步骤。

## 待办与延展

- [ ] 可落地的后续行动
- 值得进一步了解的：……

## 相关笔记

- [[已有笔记名]]
```

## 三、项目进展（10-Projects/<项目文件夹>/）

**文件名**：`<项目名>-<日期>-进展.md`（例：`网页游戏开发-2026-08-12-进展.md`），或若项目文件夹内已有进度记录类笔记则**追加新小节**。

```yaml
---
title: <项目名> 进展（YYYY-MM-DD）
created: YYYY-MM-DD
tags:
  - 项目
  - <项目名>
source: "WorkBuddy 问答归档"
---
```

```markdown
## 本期进展

- 完成/确认的事项

## 结论与决策

- 讨论后敲定的方案、依据

## 待办

- [ ] 下一步动作

## 风险与注意

- 值得留意的点
```

## 四、日记追加（20-Areas 年度记录 / YYYY-MM-DD.md）

当日日记文件存在时，将归档内容作为**一行或一小节**追加，不重写既有内容：

- 知识类内容 → 追加到 `## 📚 学习/输入` 小节下，格式：`- [WorkBuddy] <一句话摘要>（详见 [[笔记名]]，若有）`；
- 想法类 → `## 💭 想法与感悟` 下追加 `- [WorkBuddy] <一句话>`;
- 当日无日记文件 → 新建当日日记（沿用日记模板：frontmatter `日期/星期/天气/心情/标签: [日记]` + `# YYYY年MM月DD日 日记` + 四小节），再追加内容。

**追加时保留日记原有的 frontmatter 与既有小节，只增加行，不改删。**

## 命名规则

- 中文、名词性短语、简洁；无日期前缀（对话总结、项目进展除外，见上文）；无 `-NN-` 序号（MOC 专用）。
- 不含非法字符：`？ ? / \ : * " < > |`，首尾无空格。重名追加限定词。

## 标签规则

- 中文扁平标签 2-4 个，第 1 个为主题，不用层级标签。
- 库内高频标签优先复用：`软件` `服务器` `笔记方法` `整理原则` `阅读` `散文` `音乐` `美食` `游戏` `直播` `生活技巧` `知识管理` `核电文档` `写作` `项目` `MOC` `clippings` `日记`。
- 关键词标签按内容取（如 `Git` `Obsidian` `PVE`），或参考目标文件夹内既有笔记的 tags。

## MOC 更新规则

- MOC 位于主题文件夹内，命名 `-NN-主题MOC.md`，结构为 `tags: [MOC]` +（可选 `![[xx.base]]` 嵌入）+ `## 双链区`。
- 归档后若有 MOC：把 `[[新笔记名]]` 追加进 `## 双链区`（保持每行一个链接的换行风格）。
- 禁止改动 `.base` 文件；禁止自动新建 MOC。

## 库内真实样例

知识笔记（无 H1）：

```markdown
---
tags:
  - 软件
  - 服务器
---

## 核心思路

- **主分支**（`main` 或 `master`）：只放稳定可发布的代码。
- **开发新功能/修 BUG**：从最新的 `main` 拉一条新分支……合并回 `main`。
```

```markdown
---

# 2026年06月25日 日记

-

- 
```
